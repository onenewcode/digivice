## Project Technical Rules & Development Guidelines

- **Target Chip**: `esp32c6`. All dependencies, HAL features, and peripheral drivers must maintain strict compatibility with this chip.
- **Environment Constraints**: This is a pure `#![no_std]` and `#![no_main]` bare-metal embedded project. Do not introduce `std`; exclusively use `core` and lightweight embedded crates.
- **Dynamic Memory**: `alloc` is enabled. The heap is statically configured and initialized in `src/bin/main.rs` via `esp_alloc::heap_allocator!`.
- **Zero-Warning Redline**: All code must compile cleanly under `#![deny(warnings)]`, `#![deny(clippy::mem_forget)]`, and `#![deny(clippy::large_stack_frames)]`. Always maintain **0 errors, 0 warnings**.
- **Configuration & Environment**: `.cargo/config.toml` contains target runner configurations, compilation flags, and default environment variables. Espressif crate settings should be managed via environment variables rather than hardcoded in source.
- **Firmware Flashing**: Uses `espflash` (configured in `.cargo/config.toml`) over the board's native Type-C port (USB-Serial-JTAG). No external hardware probes (such as J-Link or DAPLink) are required. See [`docs/flashing.md`](docs/flashing.md) for detailed commands.
- **Logging**: Output is routed via `esp-println` over native USB-Serial-JTAG, read through `espflash monitor` or `espflash flash --monitor`. Do not add `rtt-target`.
- **Sensitive Hardware Pin Isolation**: Internal SPI Flash and bootstrapping pins (`GPIO24..=GPIO30`) are internal bus lines. Never expose, reconfigure, or assign these pins in board peripherals or user code.

## 🛡️ Microsoft Rust Training Standing Code Review Protocol (MS-Rust Auditor)

All codebase modifications, additions, and refactoring MUST be continuously audited against the **[Microsoft Rust Training](https://microsoft.github.io/RustTraining/)** guidelines and embedded Systems programming best practices:

1. **Memory Safety & Unsafe Invariants**:
   - Strictly maintain `#![forbid(unsafe_code)]` in `src/lib.rs`.
   - Deny `clippy::mem_forget` and `clippy::large_stack_frames` on all crates.
   - All shared buses must use `embedded-hal-bus` / `CriticalSectionDevice`.
2. **Type-Driven Correctness & Invariant Protection**:
   - Eliminate Boolean Blindness: Never pass raw `bool` for domain states; use strongly typed enums (e.g. `ChargeState`, `ButtonPressState`, `FaceDownTransition`, `PresenceState`).
   - Eliminate Primitive Obsession: Wrap raw values in validated domain types and defensive clamped constructors (e.g. `DateTime::new_clamped`).
3. **Panic-Free Defensive Runtime**:
   - Zero bare `.unwrap()` or `.expect()` calls in runtime loops.
   - All external inputs (USB, I2C, SPI) must return `Result` or degrade gracefully without halting the CPU.
4. **RISC-V RV32IMAC Zero-FPU Microarchitecture Efficiency**:
   - ESP32-C6 has no hardware FPU. Never call `libm` trigonometric functions (`atan2f`, `sinf`, `cosf`) in high-frequency loops; use fixed-point arithmetic, Hastings rational approximations (`fast_atan2_deg`), or compile-time precomputed LUTs.
5. **Async Concurrency & Cancellation Safety (Embassy)**:
   - Ensure all `select` and `select4` branches are cancellation-safe.
   - Async read streams (like `usb_rx_task`) must yield on EOF / zero-byte reads to prevent 100% CPU spinning.
6. **Power-Failure Resilience & Double-Buffered Storage**:
   - Flash updates must be atomic via Ping-Pong double-buffering (Sector A & Sector B) with sequence counters (`seq: u32`). Non-atomic writes are strictly prohibited.
